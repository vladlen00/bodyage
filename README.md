# Возраст тела

Мини-аппа Студии Ирены Пол. Тест из семи физических блоков, на выходе
"возраст тела" = паспортный возраст плюс сдвиг по сумме баллов.

Живёт на GitHub Pages: https://vladlen00.github.io/bodyage/

Зарегистрирована в BotFather 2026-08-05, женщины заходят по
https://t.me/relax2000_bot/bodyage

## Стек

Чистый HTML, CSS и JS без фреймворков и без сборки. Файлы лежат в корне,
как в cycle и glutes.

## Файлы

| Файл | Что внутри |
|---|---|
| `index.html` | Экраны как секции, переключаются `hidden` |
| `style.css` | Токены и компоненты, взятые из app.irenabio.com дословно |
| `norms-v1.js` | ЗАМОРОЖЕНО: пороги, шкалы и сдвиг возраста версии 1 |
| `config.js` | Выбор живой версии норм, блоки, таймкоды, таймеры и тексты |
| `calc.js` | Чистая логика подсчёта: ни порогов, ни обращений к DOM |
| `app.js` | Экраны, плеер Kinescope, таймеры, Wake Lock |

## Правило порогов

Ни одного числа порога в логике. `calc.js` умеет только арифметику над
конфигом, `app.js` только показывает.

Сами пороги лежат не в `config.js`, а в файлах по версиям. `config.js`
только выбирает живую версию и раздаёт её под прежними именами `SCORING`,
`LIMITS`, `AGE_SHIFT`, `RESULT_RULES`, `MAX_SCORE_PER_BLOCK`, поэтому
`calc.js` и `app.js` про версии ничего не знают.

## Версии норм

В каждом сохранённом замере лежит `config_version`. Он обязан указывать на
пороги, которые реально существуют в коде, иначе старый замер нечем
пересчитать, и сравнение старта с финалом в конце спринта соврёт: два конца
посчитаются по разным шкалам, не зная об этом.

Поэтому `norms-v1.js` заморожен. Он глубоко заморожен и на уровне кода
(`Object.freeze` вглубь), но главное правило человеческое: **править его
нельзя никогда**, даже ради очевидной опечатки в пороге. Строки в базе уже
посчитаны по этим числам.

Как калибровка добавит версию 2, порядок обязателен:

1. Скопировать `norms-v1.js` в `norms-v2.js` и править ТОЛЬКО копию.
2. Подключить `norms-v2.js` в `index.html` ПЕРЕД `config.js`.
3. Добавить `"2": NORMS_V2` в `NORMS` в `config.js`.
4. Поднять `CONFIG_VERSION` до `"2"`.

## Края шкалы: почему цифра иногда не двигается

Шкала относительная, и у неё есть жёсткие потолки. Их три, и все три женщина
принимает за поломку приложения, если экран молчит. Живой проход Ирены
2026-08-06 дал обе жалобы сразу.

**Потолок сдвига.** 3 балла максимум за блок, 21 максимум суммы, минус 10
максимум сдвига. В 39 лет минимально возможный возраст тела ровно 29, и
улучшить его нельзя никогда. Проверено перебором всех 16384 комбинаций
баллов.

**Потолок наступает НА БАЛЛ РАНЬШЕ максимума.** Верхняя полоса `AGE_SHIFT`
начинается с 20 из 21, поэтому цифра упирается в предел уже при сумме 20.
Рост с 20 до 21 её не двигает. Поэтому условие строки на экране - "сдвиг уже
лучший из возможных" (`atScaleTop`), а НЕ "все блоки на высший балл": иначе
женщина с суммой 20 упирается в тот же потолок и остаётся без объяснения.

**Нижняя граница возраста.** `LIMITS.resultAgeMin` = 18 плюс
`youngGuardBelowAge` = 28. При максимальном результате срабатывает с 18 до 27
лет включительно, при среднем с 18 до 21. В 18 лет с лучшим возможным
результатом цифра равна 18, сдвиг ноль, и подпись "соответствует возрасту"
читается как насмешка: для этого единственного случая подпись заменена на
"это нижний край шкалы".

**Верхняя граница недостижима.** `resultAgeMax` = 85, а худший возможный
результат в 69 лет даёт 79. Запас шесть лет. Строка `limitCeiling` в коде
есть намеренно: если однажды поднимут `entryAgeMax`, она сработает сама.

Экран показывает ОДНУ причину, самую конкретную: граница возраста первой,
предел полос вторым. К любой из них дописывается хвост про спринт, потому что
во всех трёх случаях цифра не сдвинется и через месяц.

Отдельно: слабое звено НЕ показывается, когда слабейший балл уже максимальный.
Без этого при всех тройках слабейшим назначался первый блок по порядку, и
женщина с идеальным результатом читала, что у неё проблема с сердцем.

## Сравнение старт-финал: СДЕЛАНО 2026-08-06

Экран "Старт и сейчас". **Сравниваем сырые числа поблочно, а не баллы и не
возраст тела.** Возраст тела остаётся заголовком, доказательством движения
служит строка вида "22 -> 34 подъёма".

### Как устроено

Бэкенд менять не пришлось вообще: действие `compare` в `bodyage-api` было
написано ещё в заходе 2. Без параметров оно берёт самый первый и самый
последний замер человека и отдаёт обе строки целиком, включая `answers`.
Оттуда же приезжает готовый флаг `config_changed`.

Чистый слой в `calc.js`, ни одного числа в логике:

- `blockLowerIsBetter(cfg)` - направление из формы полос: `below` значит
  меньше лучше (пульс покоя), `atLeast` значит больше лучше (всё остальное).
- `blockRawCeiling(cfg)` - потолок из `cap` (баланс, 60 секунд) и
  `startPoints` (вставание с пола, 10 за чистоту).
- `blockRawValue(id, answer)` - сырое число блока. Восстановление пульса
  идёт по ПАДЕНИЮ, вставание с пола по баллам за чистоту, секунды НЕ режутся
  потолком в отличие от `scoreBlock`: показываем введённое.
- `compareBlock` и `compareMeasurements` - строки со статусами
  `better | worse | same | ceiling | no_pair` и счётчики для шапки.

Слово `better`, а не `grew`: у пульса покоя улучшение это ПАДЕНИЕ числа.

### Два входа

1. **Экран входа**, строка-ссылка "Посмотреть сравнение со стартом". Видна,
   только если замеров больше одного (`list` с `limit: 2` при старте, без
   ожидания). Нужна потому, что иначе главный результат спринта пришлось бы
   добывать повторным прохождением теста на двадцать минут с приседаниями.
2. **Экран результата**, кнопка "Сравнить со стартом". Появляется ТОЛЬКО
   после успешного сохранения: `compare` работает по сохранённым строкам, и
   до сохранения женщина сравнила бы старт со своим ПРОШЛЫМ замером вместо
   только что сделанного.

Гостевые замеры не сравниваем ни там, ни там: они лежат общей кучей под одним
`subject='guest'`, и "первый гостевой" может оказаться другим человеком.

### Тон, проверять при любой правке текстов

Подачу приукрашивать можно, ЧИСЛА НЕЛЬЗЯ. Не писать "помолодела", если цифра
та же. Не округлять в свою пользу. Не прятать падение так, чтобы его нельзя
было найти. Пять состояний шапки:

| когда | строка |
|---|---|
| рост есть, падений нет | Выросли цифры в {n} блоках из {c}. |
| рост и падения | Выросли цифры в {n} блоках из {c}, снизились в {m}. |
| всё на месте | Цифры держатся. |
| роста нет, падения есть | Цифры пока не выросли. |
| сравнивать нечем | Сравнить пока не с чем: на старте эти блоки пропущены. |

Знаменатель `{c}` - блоки, где есть ОБА замера. Блок на потолке из
знаменателя не выкидываем: подкручивать дробь в свою пользу нельзя, а почему
он не вырос, видно в его строке ("максимум" справа).

### Цвет вместо стрелки роста

Второе число коралловое И жирное при улучшении, серое обычное в остальных
случаях. Жирность обязательна отдельно от цвета: оттенки различают не все.

Стрелки роста в правой ячейке НЕТ намеренно. У пульса покоя улучшение это
падение числа, и на одном экране пришлось бы рисовать `вниз` коралловым у
пульса покоя и `вниз` серым у восстановления пульса: две одинаковые стрелки
противоположного смысла. Стрелка на экране одна, между числами, и она
нейтральная: было и стало.

### Две оговорки, обе про то, что цифру возраста сдвинуло не тело

- **День рождения между замерами.** Возраст тела считается от паспортного,
  поэтому цифра растёт на год сама. За месяц спринта попадёт примерно каждая
  двенадцатая. Ловится как `first.age !== last.age`.
- **Пороги пересобрали.** Флаг `config_changed`. Сырые числа этим не задеты,
  и это ровно тот аргумент, из-за которого выбраны сырые числа. Пересчёта
  тут НЕТ и не будет: см. следующий раздел.

### Чего на экране нет и почему

Порогов заметности нет: показываем голые числа. Плюс два удара пульса это шум
от фазы цикла и времени замера, а не победа, и объявлять его победой нельзя.
Вердиктов по блокам тоже нет по той же причине.

### Почему сырые числа, а не баллы

Три причины, все три пригодятся, если однажды захочется "упростить":

- **У возраста тела есть потолок.** Минус десять это лучший сдвиг из
  существующих, и женщина, взявшая его на первом замере, получит в конце
  спринта ту же цифру, сколько бы она ни улучшила. Ирена упёрлась в потолок
  сразу, и без сырых чисел показать ей прогресс было бы нечем.
- **Сырое число не зависит от норм вообще.** "22 -> 34 подъёма" переживает
  калибровку `chair_stand` без единой правки, тогда как сравнение по баллам
  пришлось бы гнать через одну версию норм и объяснять пересчёт. Одним
  решением закрыт и потолок, и половина проблемы версий.
- **Работает у всех**, а не только у тех, кто на потолке. Женщине со сдвигом
  с 45 на 41 тоже нужно видеть, что именно выросло.

## Пересчёт старых замеров: решено, но НЕ сделано

Механика согласована 2026-08-06, делать её в тот момент, когда появится
версия 2 порогов, не раньше. Заморозка версии 1 - единственная часть,
сделанная заранее, потому что без неё каждый новый замер становится
непересчитываемым.

Решение: **пересчитывать на лету при показе, строки в базе не мигрировать.**
Сырые ответы плюс возраст, пол и версия полностью определяют результат,
потому что `calc.js` - чистая функция. Значит сохранённый балл это
производная величина, а не факт. Миграция превратила бы производную в факт и
отняла возможность передумать, если первая калибровка сама окажется кривой.

Что нужно будет сделать:

- На показе истории считать два числа: "как посчитали тогда" (`body_age` из
  строки, как есть) и "как считается сейчас" (прогон сырых `answers` через
  актуальную версию норм).
- Сравнение старт-финал ВСЕГДА гонит оба конца через одну версию, ту, что
  актуальна на момент показа. Иначе дельта врёт.
- Пересчитанный результат помечать на экране, например "пересчитано по
  обновлённым нормам". Женщина запомнила цифру с экрана, и молча другая
  цифра за тот же замер читается как враньё приложения ровно так же, как
  читался ноль без своего числа рядом.
- Старое число из строки не удалять никогда: это то, что она видела.
- Правило "минимум пять блоков" (`RESULT_RULES.minBlocksForResult`)
  применять в той же версии, что и пороги. Замеры с `has_age = false`
  нельзя молча оживлять после калибровки.

## Известное расхождение: подъёмы со стула

Протокол блока `chair_stand` просит КАСАНИЕ сиденья, а не полную посадку:
так снято в видео Ирены, и приложение обязано совпадать с видео.

Пороги же взяты из источника, где повтор засчитывался по ПОЛНОЙ посадке.
Касание быстрее, за 30 секунд повторов выходит больше, поэтому балл по
этому блоку сейчас ЗАВЫШЕН у всех, кто делает касанием, то есть у всей
аудитории теста.

Это осознанный компромисс, а не баг: совпадение с видео важнее. Снимается
калибровкой на живых людях, она и так в плане. Пометка продублирована в
`norms-v1.js` рядом с порогами блока.

Первая живая жалоба 2026-08-06 подсветила расхождение прямо: женщина 29 лет
сделала 22 подъёма касанием и получила 0 из 3, потому что женская норма
18-29 требует 25 по полной посадке. Расчёт при этом был честный, шкала
женская, никакой ошибки в коде не нашлось.

## Видео

Одно видео на 13 минут 09 секунд на Kinescope, к нему семь таймкодов.
Плеер подключён через IFrame Player API и создаётся ОДИН раз, переходы между
блоками идут через `player.seekTo(seconds)`.

Параметр `?seek=` в URL намеренно не используется: он обрезает начало
манифеста и отнимает возможность отмотать назад.

Видео ограничено доменом в кабинете Kinescope. Привязка к
`vladlen00.github.io` покрывает этот репозиторий.

## Тема

Светлая по умолчанию, тёмная тумблером. Ключ `irena_theme`, тот же, что на
app.irenabio.com. Тема применяется скриптом в `<head>` ДО первого кадра,
иначе будет вспышка светлого.

ВАЖНО, проверено живым проходом 2026-08-04: в Телеграме мини-аппа открывается
с того же origin `vladlen00.github.io`, что и остальные мини-аппы студии, и
`localStorage` у них ОБЩИЙ. Один раз нажатый тумблер запоминается для всех
и переживает перезапуск Телеграма, поэтому "в Телеграме всегда светлая" - неверно.
Другой origin только у app.irenabio.com.

Тему самого Телеграма мы НЕ читаем: его SDK выставляет только свои `--tg-*`
переменные, наши стили их не используют.

## Кэш

При каждой правке CSS или JS поднимать `?v=N+1` у соответствующего файла
в `index.html`. Имена файлов не меняются.

Отдельно от этого Владлен вручную поднимает `?v=` в адресе мини-аппы в
BotFather: это кэш самого `index.html` в Телеграме, внутренние `?v=` его не
пробивают. Сам GitHub Pages отдаёт `index.html` с `max-age=600`, так что без
бампа новый код доедет до всех максимум за десять минут.

## Терминология

Везде "возраст тела". Слов "биологический возраст" в интерфейсе нет нигде,
кроме дисклеймера под цифрой, где они нужны, чтобы сказать, чем результат
НЕ является.

## Текст интерфейса

Русский, на "ты", тёплый тон, нейтральный род. Женских окончаний и скобок с
окончаниями быть не должно: тест проходят и женщины, и мужчины.

Длинные и средние тире не используются нигде: ни в интерфейсе, ни в коде,
ни в комментариях, ни в коммитах. Только дефис.
